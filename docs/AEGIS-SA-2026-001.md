# AEGIS-SA-2026-001: Security Advisory for Aegis eBPF/XDP Firewall

**Date:** 2026-08-07
**Author:** Mary Jane | Red/Purple Team Architecture
**Affected Versions:** Aegis v4.3.0-rc.1 and prior
**Remediated Version:** Aegis v4.3.0-rc.2

---

## Executive Summary

During a structured security audit of the Aegis eBPF/XDP firewall (v4.3.0-rc.1), six security-relevant findings were identified. These range from a High-severity fail-open condition in the egress parser (CWE-636) and a missing IPv6 rate limiter (CWE-770), to Medium-severity logic and state-tracking flaws, and a Low-severity file descriptor leak. 

All identified vulnerabilities (except for AEGIS-SEC-003, which is an accepted architectural design documented for lock-free performance) have been remediated in **Aegis v4.3.0-rc.2**. Operators are strongly advised to upgrade to v4.3.0-rc.2 or backport the relevant eBPF object patches immediately.

---

## Findings

### AEGIS-SEC-001: TC Egress Fail-Open on Parse Error
- **Severity**: HIGH (CVSS 7.5)
- **Type**: CWE-636 (Not Failing Securely)
- **File**: `aegis-tc/src/main.rs` (line 130)
- **Description**: The TC egress firewall returned `TC_ACT_OK` (pass) when packet parsing failed, allowing malformed packets to bypass all egress blocklist, conntrack, and port scan checks.
- **Impact**: An attacker could exfiltrate data to blocked destinations by sending deliberately truncated or malformed packets that cause L4 parsing to fail, bypassing enforcement controls.
- **Remediation**: Changed error handler from `TC_ACT_OK` to `TC_ACT_SHOT` (fail-closed).

### AEGIS-SEC-002: IPv6 SYN Flood Rate Limiting Absent
- **Severity**: HIGH (CVSS 7.5)
- **Type**: CWE-770 (Allocation of Resources Without Limits)
- **File**: `aegis-ebpf/src/main.rs` (`try_xdp_ipv6`)
- **Description**: The IPv4 path implemented full SYN flood rate limiting (global + per-IP token bucket). The IPv6 path lacked any rate limiting, allowing unrestricted SYN floods over IPv6.
- **Impact**: Complete Denial of Service (DoS) via IPv6 SYN flood, entirely bypassing all rate controls.
- **Remediation**: Added `RATE_LIMIT_IPV6` and `GLOBAL_SYN_CTR_IPV6` maps with matching token bucket and global counter logic.

### AEGIS-SEC-003: Global SYN Counter PerCpu Under-Counting
- **Severity**: MEDIUM (CVSS 5.3)
- **Type**: CWE-362 (Race Condition / Concurrency Logic Error)
- **File**: `aegis-ebpf/src/main.rs` (lines 594-617)
- **Description**: `GLOBAL_SYN_CTR` utilizes a `PerCpuArray`. On an N-core system, the effective threshold is `N × GLOBAL_SYN_RATE_THRESHOLD` before any single CPU triggers the limit. There is a mismatch between the documented threshold (10,000) and the actual behavior (`10,000 × N`).
- **Impact**: Distributed SYN floods spread evenly across CPUs can evade the global threshold if configured naively.
- **Remediation**: **No code change.** This is accepted behavior by design for lock-free performance. Operators should set the threshold to `desired_rate / num_cpus`. Documentation updated to reflect this behavior.

### AEGIS-SEC-004: Port Scan Detection Bitmap Collision
- **Severity**: MEDIUM (CVSS 5.3)
- **Type**: CWE-327 (Use of a Broken or Risky Cryptographic Algorithm / Weak Hash)
- **File**: `aegis-tc/src/main.rs` (line 492)
- **Description**: The port scan bitmap tracked only the lower 8 bits of `dst_port`. Ports `N` and `N+256` aliased to the same bit, allowing scans of 256+ ports while registering as `≤256` unique ports.
- **Impact**: An attacker could evade port scan detection heuristics by scanning with stride-256 port patterns.
- **Remediation**: Replaced `(dst_port & 0xFF)` with a Knuth multiplicative hash to ensure uniform distribution across the 256-bit bitmap space.

### AEGIS-SEC-006: Pinned Map ABI Version Not Validated at Load Time
- **Severity**: MEDIUM (CVSS 5.9)
- **Type**: CWE-131 (Incorrect Calculation of Buffer Size / Type Confusion)
- **File**: `aegis-cli/src/loader.rs`
- **Description**: The eBPF loader accessed pinned maps without validating their ABI version. Stale pins from previous versions with different struct layouts could cause silent memory corruption when accessed.
- **Impact**: Silent data corruption and potential eBPF verifier bypass or kernel panic via mismatched map value sizes.
- **Remediation**: Implemented a `validate_pin_root_abi()` guard that checks pin path segments against the current `MAP_ABI_VERSION`.

### AEGIS-SEC-007: File Descriptor Leak in `freeze_map`
- **Severity**: LOW (CVSS 3.3)
- **Type**: CWE-775 (Missing Release of File Descriptor)
- **File**: `aegis-cli/src/privilege.rs` (lines 47-52)
- **Description**: The file descriptor obtained via `BPF_OBJ_GET` was only closed on a successful `BPF_MAP_FREEZE`. On freeze failure, the file descriptor leaked.
- **Impact**: Potential resource exhaustion (FD leak) in the CLI loader process if `freeze_map` fails repeatedly.
- **Remediation**: Moved `close()` to the unconditional cleanup path before evaluating the success check.
