## Bottom line

All three red-team-confirmed bypasses are closed in the datapath, fail-closed
and mirrored across XDP and TC. The conntrack feature is explicitly marked
telemetry-only (no behavioral change, only truthful labeling). The build
environment noted as broken in the audit is, in fact, healthy in this session
— both BPF programs compile and pass the eBPF verifier.

## Fixes applied

### P0-1 — IPv6 Fragment Header bypass → fail-closed DROP (aegis-ebpf, aegis-tc)

Previously, both datapaths returned `XDP_PASS` / `TC_ACT_OK` as soon as they
saw `NEXTHDR_FRAGMENT` (44), so an attacker could prepend a Fragment Header
(`frag_off=0, M=0`) to an otherwise-blocked IPv6/TCP packet and bypass every
L4 rule. This was the opposite of the IPv4 path, which is fail-closed at the
`0x3FFF` fragment mask.

Fix: in the `NEXTHADR_FRAGMENT` arm, read the 8-byte `Ipv6FragHdr` via
bounds-checked `ptr_at` and DROP, logging `THREAT_IPV6_FRAGMENT` (22) with
`REASON_IPV6_POLICY` (8). This mirrors IPv4 — all fragments (non-initial AND
first-fragment) are dropped. Policy decision (operator-approved): fail-closed
drop-all. The frag header read is bounds-checked so a truncated packet fails
closed via `?` rather than leaking an unsafe read.

### P0-2 — RH0 (Routing Header Type 0) → DROP per RFC 5095 (aegis-ebpf, aegis-tc)

RFC 5095 mandates that compliant nodes MUST silently discard RH0. Aegis
treated `NEXTHADR_ROUTING` generically via `Ipv6ExtHdr` and never read
`routing_type`, so RH0 packets reached L4 processing.

Fix: `NEXTHADR_ROUTING` now has its own match arm. The `routing_type` byte
(3rd byte of the routing header) is read bounds-checked; if it equals
`ROUTING_TYPE_0` (0) the packet is DROP'd with `THREAT_IPV6_ROUTING_TYPE0`
(21). RH2 (Mobile IPv6) and SRH (routing_type != 0) are walked past
generically and pass through unchanged.

### P1-1 — Spoofable whitelist trimmed (aegis-ebpf)

The XDP ingress whitelist auto-trusted `100.64.0.0/10` (CGNAT) and
`127.0.0.0/8` (loopback) before any deny check. On an internet-facing
interface these are not trust boundaries — a spoofed source in those ranges
bypassed every deny rule.

Fix: trimmed to true RFC1918 only — `10/8`, `172.16/12`, `192.168/16`.
Operators who need to trust a CGNAT/loopback source must add it explicitly to
the ALLOWLIST map. (The userspace heuristic in `map_manager.rs` that sets
`CFG_SKIP_WHITELIST=1` on non-virtual interfaces remains as defense-in-depth;
this fix closes the bypass at the BPF layer directly.) Policy decision
(operator-approved): trim, not gate-behind-flag.

A new **warning-only** `check_rp_filter()` preflight in `install.sh` advises
`rp_filter=1` on the protected interface (the kernel-side anti-spoofing
complement). It always returns 0 and never fails an install, so it cannot
break lab/test/asymmetric-routing setups.

### ESP (IPsec) passthrough restored (aegis-ebpf, aegis-tc)

`NEXTHADR_ESP` (50) was defined but absent from the ext-header match arms, so
ESP traffic was silently dropped by the walker's default fail-closed path.
Added as a terminal L4-like payload (`is_valid_l4 = true; break;`) so IPsec
is not spuriously dropped.

### Conntrack marked telemetry-only (aegis-cli, aegis-common)

The conntrack feature is telemetry-only in this release: no BPF program ever
increments `conntrack_hits`, `CFG_CONN_TRACK` is written by userspace but read
by no BPF program, and the handshake state machine in `aegis-common` is
aspirational. Rather than remove the dead surface (which would risk breaking
config parsing or Prometheus scrape consumers), the status is made truthful
everywhere an operator might see it:

- Prometheus `# HELP` for `aegis_conntrack_hits_total` now states it is always
  0 and points at `aegis_conntrack_entries` as the real signal.
- The TUI summary + detail panel, the HTML dashboard card, and the
  `aegis status` CLI print all label the value as telemetry-only.
- The `CFG_CONN_TRACK` write in `map_manager.rs` and the constant definition
  in `aegis-common/src/lib.rs` carry explanatory comments.

Policy decision (operator-approved): stay telemetry-only, strip misleading
bits, do NOT wire up an established-flow fast-path incrementally. Scoping a
real conntrack security control (seq validation, handshake tracking, asymmetric
routing, map-pressure accounting) is deferred to a later release.

## Policy decisions (all operator-approved)

| Decision | Choice | Rationale |
|---|---|---|
| IPv6 first-fragment (offset=0, M=1) | Fail-closed drop | Mirrors IPv4; most defensible for public-facing firewall |
| RFC1918/CGNAT whitelist | Trim CGNAT + loopback | CGNAT is not a trust boundary; loopback never traverses XDP |
| Conntrack | Telemetry-only, label truthfully | No datapath change; real security-control design deferred |
| Verification level | Compile + ABI + scapy scripts | No dedicated lab NIC in this session |
| `MAP_ABI_VERSION` | Stay at 1 | No struct-layout change; bump would needlessly drop pinned-map state on upgrade |

## Not proven in this session

Runtime verdict enforcement (packet actually DROPPED, threat-type actually
logged) requires a lab NIC + `CAP_BPF` + root + scapy, none of which are
available in this environment. Operator-run regression scripts are provided
under `test/` to close this gap on a lab machine:

- `test/ipv6_fragment_bypass.py` — crafts the P0-1 bypass packet, asserts DROP.
- `test/ipv6_rh0_bypass.py` — crafts an RH0 packet, asserts DROP (+ RH2 control).
- `test/ipv4_spoof_cgnat.py` — crafts a spoofed `100.64/10` source, asserts it
  is no longer auto-whitelisted.

Each script self-documents prerequisites, expected verdict, and the exact
`threat_type` / `reason` bytes to grep for in the event stream. They are
**not** run in CI.

## Residual known limitations (read before deploying)

1. **Conntrack is telemetry-only.** Do not rely on it for enforcement. The
   `conntrack_hits` counter will read 0; that is expected. See the conntrack
   section of the red-team audit for why a real fast-path is not wired up.
2. **TC egress is fail-open on parse error** (`Err(_) => TC_ACT_OK`). This is
   an explicit egress convention, not a bug — only the new fail-closed
   fragment/RH0 branches deliberately DROP. Documented inline in
   `aegis-tc/src/main.rs`.
3. **1500-byte cap on `l4_offset`** is an absolute offset from the L2 frame,
   not relative to `payload_len`. A medium-severity semantics gap exists where
   an attacker can declare a tiny `payload_len` while embedding a fake
   extension chain that pushes `l4_offset` toward 1499; the kernel computes a
   different L4 offset. Also, jumbo frames (up to 9000 bytes) and TSO/GSO
   egress packets are spuriously dropped by this cap on jumbo-enabled NICs.
   Deferred to a separate hardening pass.
4. **HBH-not-first (RFC 8200 §4.1)** is not enforced; a Hop-by-Hop Options
   header appearing later than immediately after the fixed header is parsed
   identically to the canonical order, diverging from the kernel's strict
   parser. Deferred.
5. **IPv6 fragmented traffic cannot pass.** This is the intended trade-off of
   the P0-1 fix (fail-closed drop-all, mirroring IPv4). PMTUD normally avoids
   IPv6 fragmentation on the modern internet; if a specific flow requires it,
   the operator must exempt that path outside Aegis.
